thriveERP — Ground Rules (Draft)
=================================
Status: Draft — expand/edit as the team grows or conventions get decided.

1. GUIDING PRINCIPLE
---------------------
KISS. Build for what we need now. The pluggable/hexagonal structure exists so
we CAN swap pieces later — it is not permission to build every piece now.
If a decision doesn't need to be made this sprint, write it down as deferred
(see DesignLogic.md / ARCHITECTURE.md) and move on.

2. MODULE BOUNDARIES
---------------------
- core-domain must never import a framework (no Spring, no JPA annotations,
  no Jackson). Pure Java only.
- core-app talks to ports (interfaces), never to a concrete adapter class.
- Adapters (persistence, rest, erp-impl, audit) never talk to each other
  directly — everything flows through core-app / core-domain.
- If you're tempted to import adapter-persistence from adapter-erp-impl,
  stop — that's a sign the interaction belongs in core-domain instead.
